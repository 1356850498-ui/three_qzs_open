# 大模型协作提示词工作流

以下模板用于按接口、日志和报告开展排错。模板是使用方法，不是历史对话原文。

## 步骤一：冻结契约并设计独立验证

```text
我正在验证一个 FPGA RTL 模块。以下提供目标功能、时钟/采样沿、接口、参数范围、现有 RTL 和测试。
[粘贴真实接口、规范、文件版本及代码片段]
请先列出仍不明确的契约，再给出可由外部输入独立计算期望输出的行为模型。
逐项列出正常、首帧、边界、复位、启停、非法参数、故障和同拍优先级测试。
说明内部哪些信号只能当被检查量，哪些期望量需要独立生成。
不要仅凭波形外观或复制 DUT 内部算法就认定正确。未提供的信息标为未知。
给出每项测试的输入、期望事件、终止条件和结果文件格式。
```

## 步骤二：失败定位与最小修改

```text
以下是同一版本的契约、最早失败位置前后若干拍、编译/仿真日志和相关 RTL。
[粘贴实际失败证据；列出路径、top、参数、时间/周期号和版本]
请区分已证实事实与假设。按优先级给出根因候选、区分候选的最小实验，
以及有明确原因的最小修正。每个修正列出可能改变的接口时序和必须重跑的测试。
如果证据不足，不要编造运行结果；指出需要哪段日志或哪个输入才能判定。
不要为了让测试通过而删除检查、改写黄金答案或放宽原始验收条件。
```

## 步骤三：实现瓶颈与优化取舍

```text
以下是同配置的 routed timing summary、hierarchical utilization、关键路径及相关 RTL。
[粘贴真实报告，注明工具版本、器件、top、时钟与报告阶段]
请先提取 WNS/TNS/WHS/THS、时钟、LUT/FF/BRAM，并指出未约束路径/告警。
依据真实路径说明瓶颈，提出少量可验证的优化候选，写清延迟、资源、复位、接口代价。
不要把综合估计等同最终实现，不用删约束换取“时序通过”。
为每个候选给出功能回归、接口时序复验和实现前后对比方法。
只有实际执行后才填写优化效果，尚未执行的方案标为待验证。
```

## 步骤四：把真实结果送回并纠错

```text
按上一轮建议实际运行后的结果如下：
[粘贴真实命令、版本、退出码、result 文件和新报告；失败也完整保留]
请核对原假设哪些成立、哪些被否定；更新根因判断，不把旧 PASS 用在新版本。
若修正产生回归，先解释新失败和修改之间的关系，再提出下一项最小实验。
最终按“触发条件—定位—修正—复验—失效条件”总结可跨题复用的经验。
明确哪些是仿真结论、内部实现时序结论、实板结论；没有证据的层级标为未验证。
```

协作记录每轮至少保存：日期、模型或工具的实际显示名称、输入、回答、采纳/拒绝理由、执行命令、实际结果、下一轮修正。模型版本未知时写未知，不能推测。模板不自动完成原始协作记录的提交要求。

# 独立验证契约

使用顺序：在让模型改 RTL 前填写契约，再写测试，再看结果。以下是可跨题复用的框架；本队具体数值只作为例子。

| 契约项 | 必须明确的内容 | 本工程已有例子 |
|---|---|---|
| 采样与生效 | 输入在哪个沿采样、输出何时可见、允许多少拍延迟 | 100 MHz；比较结果在采样沿后生效 |
| 合法输入 | 参数范围、参考边界、非法值处理 | 主 D=200000 ppm；非法配置拒绝运行并锁存错误 |
| 正常输出 | 合法状态、时序间隔和通道关系 | 12 路命令，普通换向等待 100 拍，禁止 1111 |
| 窗口统计 | 半开区间、相邻窗如何计数、并集是否去重 | D=0.2 每单元每周期 ST 并集 2000 拍；不能只数脉冲个数 |
| 启动/停机 | 首帧、等待点、重复启停、停机后状态 | 各单元等待本地谷值，不从中途窗口直接插入 ST |
| 复位/故障 | 断言/释放、锁存、清除、同拍优先级 | 复位与故障优先，清除不自动重启 |
| 多通道关系 | 共同时基、固定相差、漂移限值 | 载波延迟 0/1667/3333 拍；共同基波参考 |
| 覆盖终止 | 覆盖多少周期与哪些边界才可结束 | 主测试覆盖超过两个完整 50 Hz 周期及中断/重启 |

黄金模型从输入及接口规范独立计算事件。不要把 DUT 的内部 carrier、ref_index 或 started 直接用来生成期望 gate；它们可以与独立期望量比较。若复制相同算法是必要的，额外增加另一种表示方法、手算边界或独立不变量，明确共同错误风险。

为每种异常建立“输入—期望—证据文件”记录。比较首个错误拍，给出前后若干拍的输入、期望和实际，不只给总失败数。自检测试结束时写入一行 RESULT=PASS 或 RESULT=FAIL，并写 ERRORS 数值；中途退出不得沿用旧 PASS。先写 RESULT=INCOMPLETE，成功结束后再写最终值。

D0 是独立功能配置，不等价于移除所有延迟。模块替换后必须重新确认接口时序，再决定是逐拍等价还是有界延迟等价。不要将旧单单元的等价结果外推成新级联路径的逐拍等价。

测试结果按实际 testbench 能覆盖的范围表述。检查次数不是独立场景数，也不是形式覆盖率。对其他 PWM、SPI、UART、运动控制等题目，保留契约结构，换成其握手/帧/状态与时间约束。
